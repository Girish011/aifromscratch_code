LLM optimization mountain

A bottom-up map of the main optimization layers in an LLM system, starting from hardware and ending at user-visible behavior. This view helps separate infrastructure choices from model changes and from runtime steering.

Bottom = foundational constraints
Top = closest to end-user behavior
Useful for training, serving, and agent systems
Layer 1
Hardware and infrastructure
The physical base: GPUs, HBM/VRAM, interconnects, storage, host memory, networking, and scheduler choices. These determine what model size, batch size, throughput, and latency are even possible.
GPU memoryHBM capacity, bandwidth, VRAM fit.
InterconnectNVLink, PCIe, InfiniBand, Ethernet.
Storage + cacheCheckpoint load, KV spill, dataset IO.
Cluster orchestrationScheduling, autoscaling, placement.
Layer 2
Serving and systems optimization
How the model is executed efficiently in production. This includes batching, KV cache policy, kernel fusion, speculative decoding, and parallelism strategies across one or many GPUs.
BatchingStatic, dynamic, continuous batching.
ParallelismTensor, pipeline, data, expert, context.
KV cacheReuse, paging, prefix caching, eviction.
Decode tricksSpeculative decoding, fused kernels.
Layer 3
Model weights and architecture
Changes to the model itself: pretraining recipe, fine-tuning, LoRA adapters, quantization, pruning, distillation, MoE routing, and context extension methods.
Fine-tuningSFT, instruction tuning, domain tuning.
LoRA / PEFTParameter-efficient weight updates.
QuantizationINT8, INT4, AWQ, GPTQ, FP8.
ArchitectureDense vs MoE, long-context, distillation.
Layer 4
Behavior shaping and steering
Control techniques that alter the model’s tendencies without necessarily retraining the whole base. This is where prompt engineering, activation steering, guardrails, and policy shaping sit.
Prompt engineeringSystem prompts, templates, examples.
Activation steeringSteering vectors, suppression, promotion.
Alignment layerPreference shaping, policy constraints.
GuardrailsSafety filters, validation, tool policies.
Layer 5
Application and agent runtime
The top layer closest to user experience: RAG, memory, tool use, planners, routers, retries, evaluators, and UI. This is where an end-to-end product feels smart or weak.
RAGRetrieval, reranking, chunking, grounding.
Agent orchestrationTools, planners, workflows, retries.
MemorySession state, long-term memory, profile.
EvaluationTracing, feedback loops, observability.

Rule of thumb: lower layers improve efficiency and capacity, while upper layers improve control and product behavior. Steering belongs above weight changes but below application orchestration.
